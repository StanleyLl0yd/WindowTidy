# Repository-wide audit and refactoring - 2026-10-09

## Baseline and scope

Baseline: `a192ed7305a271c198f267e8e9aab1bc1463fde2` (`main` on audit start).

This review covers **every tracked file** in the baseline and a second full pass over the updated repository, not just the patch: `src/`, `include/`, `tests/`, `res/`, `scripts/`, `.github/workflows/`, `.gitignore`, `.gitattributes`, `AGENTS.md`, `README.md`, `ROADMAP.md`, and `SECURITY.md`. Inspected Win32 entry points, dialog/resource identifiers, global hotkey registration, HWND filtering, registry reads/writes, monitor calculations, shell integration, process lifecycle, build flags, native imports, manifest, automated tests and release constraints. Changes were applied in small commits and verified with Windows CI.

## Findings fixed

| Priority | Finding | Resolution |
| --- | --- | --- |
| High | A single global shortcut collision disabled **all** other shortcuts at startup. | Register available shortcuts individually at startup. Keep strict all-or-none validation for Settings. Add a native Windows integration regression that occupies Alt+H and checks Ctrl+Alt+Z remains registered. |
| Medium | Explorer restarting before the notification area becomes ready could permanently lose the tray icon. | Retry only after failed registration; stop the timer on success; try NIM_MODIFY if the icon is already present. |
| Medium | Large stack buffer for HKCU Run settings triggered MSVC analyzer warning C6262. | Dynamically size a bounded read buffer after querying the registry value length. |
| Medium | Presence check ignored valid expandable (`REG_EXPAND_SZ`) Run entries. | Recognize either supported Windows startup string type without expanding environment variables. |
| Medium | When taskbar focus replaced the active window, tray commands could silently do nothing. | Disable window-specific tray commands when no eligible target can be identified. Full UX solution remains issue #3. |
| Low | Duplicate `g_tidyActive` state had to stay synchronized with recorded HWNDs. | Derive Undo eligibility directly from the recorded vector; remove redundant boolean state. |
| Low | Resource control clearing depended on numeric relationships between unrelated IDs. | Use explicit control ID array. |
| Low | Shortcut validation accepted modifier virtual-key variants as action keys. | Reject left/right Ctrl, Alt and Shift virtual keys and cover cases with tests. |
| Low | Win32 `wWinMain` lacked Windows SDK SAL annotations under `/analyze`. | Match the annotated Win32 signature. |
| Low | Unneeded settings copy during enumeration and unused header inclusions. | Use a reference in TidyContext and remove redundant includes. |

## Removed

Redundant Tidy status boolean and related updates, unused header includes, duplicate settings copy.

No source files, public APIs, resources, supported functions, compatibility branches or dependencies were deleted without proving them unnecessary.

## Consolidated and simplified

- One authoritative Tidy state (the vector of windows minimized by Window Tidy).
- Strict Settings hotkey validation vs partial availability at program startup.
- Explicit mapping between the five Clear buttons and their hotkey controls.
- Idempotent tray-add logic, with a retry timer **only when registration fails**.
- Registry autostart read supports the two legitimate string value types.

The existing compact Win32 architecture, single native UI thread and direct Windows API calls remain. Splitting `src/main.cpp` into artificial classes/modules or adding framework abstractions was rejected as unproven complexity reduction.

## Dependencies and supply chain

Runtime third-party dependencies: **0 before / 0 after**. No .NET, Qt, MFC, Boost, installer, hooks, injection, drivers, services, user telemetry, or network code. MSVC CRT is linked statically. Windows imports and the embedded PerMonitorV2/asInvoker manifest are checked by CI. GitHub Actions uses pinned SHA references for checkout and artifact upload, with read-only token permissions.

## Validation

The Windows workflow executes:

1. MSVC C++20 x64 compilation with `/W4 /WX /analyze /MT`.
2. Logic and geometry regression tests.
3. Native Windows integration test for shortcut collisions.
4. PE import validation to exclude dynamic MSVC CRT.
5. Embedded application manifest verification.
6. Real Windows process launch smoke test.
7. SHA-256 generation and unsigned EXE artifact creation.

The integration test reproduced an Alt+H collision and **passed**, confirming the Tidy hotkey stays reserved. The implementation is not considered released until the exact final commit passes CI.

## Intentionally unchanged / remaining risks

- Existing UI text/layout, Ctrl/Alt/Shift hotkey control (no Win modifier in this control), tray workflow, and three monitor movement modes are preserved.
- GUI-specific acceptance on real interactive Windows 10/11 desktops, different DPI scaling, monitor hot-plug, nonstandard/UWP/elevated windows, and actual Tidy/Undo behavior remains open in [#2](https://github.com/StanleyLl0yd/WindowTidy/issues/2).
- Reliably recovering the intended target after shell focus steals it, without global keyboard hooks or guessing a different window, needs UI/desktop testing in [#3](https://github.com/StanleyLl0yd/WindowTidy/issues/3). Current safe behavior is to disable the affected tray menu commands if no target is known.
- HWND reuse within the same PID, window refusal to accept position changes, and user changes to minimized windows during a Tidy session cannot be exhaustively proven by headless tests.
- Registry writes span multiple values and are not an atomic transaction. On exceptional partial write failure the UI displays an error; there is no claim of guaranteed rollback.
- No public license has been selected ([#4](https://github.com/StanleyLl0yd/WindowTidy/issues/4)).
- No code signing, release publication, or physical-multi-monitor testing was performed during this repository review.

**Release gate:** do not tag `v0.1.0` until issue #2 acceptance is complete. Versions must remain numerical `MAJOR.MINOR.PATCH`.
